# 规范

## 使用推荐

### 指针 & 引用

入参用引用，出参用指针。
传入参数：只读不修改，传 `const&`。
传出参数：先读后写，传 `*`。

### 参数传递

`const&` vs `&&`

`const&` 可以接受左值和右值，避免不必要的拷贝。
`&&` 只能接受右值。

选择：对于函数内部需要拷贝资源的可以使用 `&&` 直接转移所有权。

所有需要拷贝的参数，都要考虑能否使用不拷贝的形式。

### 代码块注释

可以使用如下形式注释代码块，清晰快捷。

```C++
#if 0
// ...
#endif

#if 1
// ...
#endif
```

### 注释特例

It's a comment designed to be read by a static analysis tool to tell it to shut up about this line.

```C++
// NOLINT
```

用于关闭 clang-format 检查。

```C++
// clang-format off
// clang-format on
```

#### 静态检查

这些是 Clang Static Analyzer 中的检查规则：
`clang-analyzer-cplusplus.NewDelete`：检查 C++ 代码中动态分配内存时可能出现的 new 和 delete 使用不匹配的问题。
`clang-analyzer-cplusplus.NewDeleteLeaks`：检查 C++ 代码中由 new 分配但未正确释放内存（导致内存泄漏）的情况。
具体作用：
`// NOLINTBEGIN(clang-analyzer-cplusplus.NewDelete,clang-analyzer-cplusplus.NewDeleteLeaks)`：
从此注释开始，告诉静态分析工具忽略 NewDelete 和 NewDeleteLeaks 的检查规则。
配套的 `// NOLINTEND`：
指示静态分析工具从这一行起，重新启用这些检查规则。

## 可读性

- 命名注意单复数，命名的 `vector` 或其他类型，使用复数。
- 使用 using 命名较长的类型，增加可读性。

```C++
// example
using pb_feeds_items_t = google::protobuf::RepeatedPtrField<FeedsItem>;
```
