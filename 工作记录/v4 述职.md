# 述职

## 当前岗位工作回顾

1. 全链路透明化建设

- 背景
上下游链路在实验场景和 dispatcher 异常率和耗时无法对齐，无法快速定位问题。
- 动作
Merger 埋点统计各实验场景耗时、异常率、候选、打分等，支持多模型分开上报耗时、打分等数据。
Merger/Hub 监控面板改造。
改造前：
个性化场景->Merger->Hub->Thor
改造后
个性化场景<=>前端实验场景<=>Merger<=>Hub<=>Thor

- 效果
Merger/Hub/Thor 支持根据实验场景统计耗时 + 异常率。
助力算法同学加速定位如打分异常、候选突变等问题。
根据流量情况统计资源使用情况。

2. Merger - 相关性链路升级

- 背景
相关性精排链路需要获取到 Bert 模型打分后将 BertScore 作为 Context 特征，到 LGB 模型中返回精排分。
- 动作
先缓存获取 Bert 分数，未获取到的 item 拼成新 request 请求 Bert，将有 BertScore 的 item 合并作为 LGB 的 request。
再将 BertScore 和 LGBScore 一起返回。
- 效果
用户在全场景：转化率 +0.45%（P 值=<0.0001）, UV 金额 +0.6%（P 值=0.0015）, IPV +0.48%（P 值=<0.0001）。
用户在场景内：转化率 +0.74%（P 值=<0.0001）, UV 金额 +1.02%（P 值=<0.0001）, IPV +0.71%（P 值=<0.0001）。

3. Merger - 图搜链路改造

- 背景
图搜仅支持图片向量召回，在图片识别分类不准确的情况下，很容易直接就获得了类目不相关的结果。且当前图像召回结果的相关较少，对排序贡献有限。
- 动作
支持图搜 img_ocr 字段解析，用于搜索和相关性构造 Context 特征。
相关性链路支持缓存获取 item vec 并与 query vec 计算 QI 相似度。
- 效果
全站转化率 +0.79%（P 值=0.006）, UV 金额 +1.11%（P 值=0.0384）, IPV +0.37%（P 值=0.1212）
场景内转化率 +4.66%（P 值=<0.0001）, UV 金额 +5.07%（P 值=<0.0001）, IPV +7.55%（P 值=<0.0001）

3. 创意召回服务使用 RocksDB Cache

- 背景
创意召回服务使用 oxygen::Cache 模块获取创意资源缓存，导致使用内存、查询 RocksDB 耗时较高。
- 动作
使用 RocksDB LRU 缓存替换 oxygen::Cache。
- 效果
内存使用下降约 80%（43%->8%）。
调用创意召回接口耗时最高下降 32%（2ms->1.35ms）。
RocksDB miss 率下降 68%（80%->25%）。
